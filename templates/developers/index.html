Mercfy API · v1.0

Build apps with music & quotes.

REST API for developers. Fetch published music and quotes from Mercfy using a simple Bearer token.

https://mercyfy.dutoza.com

Getting Started

Three steps to start calling the API. Tap a step to read the details.

1 Get an API keyRegister as a developer and create a key from the dashboard.

An API key identifies your app on every request. Creating one takes about two minutes.

  1. Create a developer account. {% if developer_logged_in %}You are already signed in, so you can skip this.{% else %}Open Create account and enter your name, email and a password (at least 8 characters). Already registered? Log in.{% endif %}
  2. Open API Keys in your dashboard. Scroll to the Create New API Key form.
  3. Fill in the form. Tell us what you are building (see the fields below) and accept the terms.
  4. Copy your key. It starts with dutoza_ and is shown only once, right after you create it.

What the form asks for

FieldRequiredWhat to enter
Key nameNoA label for you, e.g. My App - Production. Defaults to Developer API Key.
ServiceYesQuotes, Music or Quotes + Music. Choose only what you need.
How you will use the APIYes10 to 500 characters describing your project and what you will do with the data.
Project typeYesMobile app, Website, Backend / Server, or Learning / Personal.
Expected requests per dayNoUnder 1,000, 1,000 to 10,000, or over 10,000. It helps us set a fair rate limit.
Website or app linkNoMust start with https:// or http://.
TermsYesYou agree not to resell or redistribute the content, to credit Mercfy where required, and to keep your key private.

When does my key start working?

Service you choseStatus after you submit
QuotesACTIVE Works immediately.
Music or Quotes + MusicPENDING APPROVAL An administrator reviews your request first. Once approved it becomes ACTIVE. If it is declined you will see REJECTED with the reason, and you can submit a new request.
Good to know
  • You still receive your key right away, even when approval is pending. Save it: it will start working as soon as it is approved.
  • You can have up to 3 requests waiting for approval at the same time, and you can cancel a pending request from the Keys page.
  • A key only works for the services you selected. Calling another service returns 403 Scope not allowed.
  • Lost your key? You cannot view it again. Revoke it and create a new one.

2 AuthenticateSend the key in the Authorization: Bearer header.

Every request must include your key in the Authorization header, using the Bearer scheme: the word Bearer, one space, then your key.

Authorization: Bearer dutoza_your_api_key_here

Examples

{% raw %}curl "https://mercyfy.dutoza.com/api/quotes/" \ -H "Authorization: Bearer YOUR_API_KEY"{% endraw %}

Keep your key safe

  • Store it in an environment variable or your server's secret manager.
  • Call the API from your backend. For a mobile app or website, let your own server call Mercfy and pass the results on.
  • Never commit it to GitHub or put it in browser JavaScript or an app bundle. If it leaks, revoke it and create a new one.

Next: Call endpoints →
3 Call endpointsRequest /api/quotes/ or /api/music/ and use the JSON response.

The base URL is https://mercyfy.dutoza.com. Here is a first request that returns five Swahili quotes:

{% raw %}curl "https://mercyfy.dutoza.com/api/quotes/?per_page=5&language=sw" \ -H "Authorization: Bearer YOUR_API_KEY"{% endraw %}
Keep the trailing slash on list endpoints: /api/quotes/ and /api/music/. Without it the server answers with a 308 redirect, and tools such as curl will not show any data unless you add -L.

Available endpoints

Quotes (needs Quotes access)
  • GET/api/quotes/ list quotes
  • GET/api/quotes/{id} one quote
  • GET/api/quotes/categories all categories
Music (needs Music access)
  • GET/api/music/ list songs
  • GET/api/music/{id} one song
  • GET/api/music/artists and /albums
  • POST/api/music/{id}/play count a play
  • POST/api/music/{id}/download count a download, returns audio_url

Query parameters for list endpoints

ParameterWorks onDescription
pageQuotes, MusicPage number, starting at 1 (default 1).
per_pageQuotes, MusicItems per page, from 1 to 100 (default 20).
qQuotes, MusicSearch text.
languageQuotes, MusicFilter by language, for example sw or en.
sourceQuotes, Musicadmin for content published by Mercfy, user for community content.
user_idQuotes, MusicOnly content from one user.
categoryQuotesA category slug from /api/quotes/categories, e.g. motivation.
artist, albumMusicAn artist or album slug or id.
genreMusicGenre name, for example gospel.

What the response looks like

List endpoints return the items in data, together with paging details:

{% raw %}{ "success": true, "page": 1, "per_page": 5, "total": 134, "pages": 27, "data": [ { "id": 12, "text": "Mafanikio huanza kwa hatua ya kwanza.", "author": "Dutoza", "category": "Motivation", "category_slug": "motivation", "language": "sw", "created_at": "2026-10-01T09:30:00+00:00", "user_id": null, "source": "admin", "user": null } ] }{% endraw %}

A song contains id, title, slug, description, lyrics, audio_url, cover_url, duration_seconds, track_number, genre, language, release_date, play_count, download_count, an artist object, an album object, created_at, user_id, source and user.

Single-item endpoints return the same item under data. When something goes wrong you get "success": false and an error message.

Read all pages

{% raw %}let page = 1, pages = 1; while (page <= pages) { const res = await fetch( `https://mercyfy.dutoza.com/api/music/?per_page=100&page=${page}`, { headers: { Authorization: `Bearer ${process.env.DUTOZA_API_KEY}` } } ); const json = await res.json(); pages = json.pages; // total number of pages // ...use json.data here... page += 1; }{% endraw %}

Stay within your rate limit

Each key has a limit of requests per minute (the default is 100). Every successful response tells you where you stand:

HeaderMeaning
X-RateLimit-LimitRequests allowed per minute for this key.
X-RateLimit-RemainingRequests left in the current minute.
X-RateLimit-ResetSeconds until the counter resets.

If you go over the limit you get 429 Too Many Requests with a Retry-After header (and a retry_after field in the body), the number of seconds to wait before trying again.

Security

      
Best practices when integrating the API.

      

        

          
Do

          
Store keys in server env vars. Use HTTPS only. Rotate keys if leaked.

        

        

          
Don’t

          
Hardcode keys in mobile apps or public frontend JS. Don’t share keys between teams without tracking.
